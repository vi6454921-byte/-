# Рагдолл и stumbling · v6

Полная сборка на основе v5. Запуск прежний: распаковать весь архив в отдельную папку, запустить `start-server.bat` либо `sh start-server.sh`. Нужны Python и браузер с WebGL 2; Node/npm для игры не нужны.

## Обычный игровой рагдолл

- 15 динамических сегментов тела вместо 11: отдельно движутся кисти и стопы. Оружие на ремне — дополнительное динамическое тело.
- Многоосевые суставы позвоночника, шеи, плеч, тазобедренных суставов, запястий и голеностопов с ограниченными диапазонами. Колени и локти остаются шарнирами; исправлена ось локтя при почти прямой опущенной руке.
- Самоколлизии с исключением близких суставов/перекрывающихся центральных сегментов. Это не коллизии пальцев, одежды и всех предметов экипировки.
- Наследуются горизонтальная и вертикальная скорость контроллера, а также ограниченная относительная скорость движущихся ног/корпуса. Попадание в лежащее тело передаёт локальный импульс с плечом силы, а не скорость всему телу сразу.
- Меньше гашения вращения в воздухе; при контакте включается более сильное затухание. Покой требует реальной опоры и низкой скорости, а не просто истечения таймера в воздухе.
- Короткий остаточный тонус и ограниченная защитная реакция рук у сознательного падающего; при потере сознания тонус быстрее угасает. Нет подвеса таза к миру или компенсации гравитации.
- При ударах корпусом о поверхность воспроизводится звук падения. Сохранены взаимодействия с медиком, перетаскивание и отдельная физика оружия.

## Stumbling

Система включена в обычной игре у игрока и NPC, а не только в body-lab.

Причины: попадания (особенно в ноги), быстрые столкновения, зацеп за низкое препятствие, жёсткое приземление. Усталость и хромота уменьшают запас устойчивости. Ходьба по ровному месту не вызывает случайных падений по таймеру.

Последовательность: пошатнулся → компенсационный шаг → вернул устойчивость. Если возмущение слишком сильное или повторяется, происходит переход в динамическое падение. Низкая преграда отличается от высокой стены по геометрии коллайдера; удар о стену сам по себе не считается зацепом стопы.

Во время реакции снижаются скорость и прицеливание, появляются сгибание корпуса и движение таза. Без оружия руки разводятся для баланса. С оружием обычный хват сохраняется до падения; при падении оружие переходит на физический ремень. Во время лежания и подъёма стрельба/новая перезарядка блокируются.

## Нефатальное падение и подъём

Потеря равновесия не вызывает onDeath и не обнуляет ранения/физиологию. Временный рагдолл использует ту же артикуляцию, что и раненый/убитый персонаж, но не является смертью.

Подъём начинается только после замедления тела, наличия опоры и проверки свободного объёма около таза. Под низким потолком подъём блокируется или завершается в низкой стойке. Без сознания, с отключившимися ногами или после перехода в медицинскую недееспособность автоматического подъёма нет. Препятствие убрано — попытка повторяется. Смертельное попадание во время временного падения переводит тело в обычный рагдолл раненого/убитого; баланс не оживляет его.

Для игрока на время падения/подъёма камера отходит от тела, учитывает препятствия и не скрывает голову. После восстановления возвращается прежний режим. Внизу экрана отображается состояние равновесия; радиосообщения не заменяются.

**Подъём гибридный:** физическое падение и опора проверяются Rapier, затем используется плавное анимационное смешивание через низкую стойку. Это не полностью физическое вставание с динамическим переносом веса на ладони/колени. Контакт каждого визуального сегмента при всём переходе не гарантируется. Полный самобалансирующийся active-body из экспериментального стенда не включён и его прежние ограничения не объявлены решёнными.

## Нагрузка и проверки

Для быстрых падений обычные бодрствующие рагдоллы используют два подшага Rapier по 1/120 с внутри игрового тика 1/60 с. Если все обычные рагдоллы спят, дополнительное дробление не требуется. Экспериментальный active-body сохраняет прежний шаг. Это повышает стоимость физики при массовых падениях; прирост FPS на видеокарте пользователя не заявляется.

Результаты текущего выпуска: `docs/RAGDOLL_STUMBLING_QA_V6.json`; изменённые файлы: `docs/RAGDOLL_CHANGED_FILES_V6.json`. Тесты не гарантируют отсутствие пересечений на каждом препятствии, во всех сочетаниях экипировки и во всех боевых ситуациях.

Известный отдельный старый сбой `runtime.cjs:167` («occluded target position is not tracked») сохраняется с v4/v5; модуль combat не изменён. Поэтому общий `npm test` не объявлен полностью зелёным.

## Диагностика разработчика

```sh
npm run build
npm run typecheck
npm run test:ragdoll
npm run test:ragdoll:browser
npm run test:locomotion
```

Для браузерного теста запустить локальный сервер, при необходимости задать `BASE_URL` и `CHROMIUM_PATH`. Примеры в консоли игры:

```js
__GAME.stumble(0, 0.55, [1, 0, 0]); // умеренная потеря равновесия
__GAME.stumble(0, 1.4, [0, 0, -1]); // временное физическое падение
__GAME.bodyImpulse(0, [20, 0, 0]);  // импульс лежащему телу / возмущение стоящего
__GAME.balanceStats();
```

Индексы соответствуют бойцам в текущем squad. Эти функции — диагностические; обычное срабатывание от контактов и попаданий не требует консоли.
